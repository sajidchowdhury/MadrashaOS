   130→## Naming Conventions
   131→
   132→| Convention | Rule | Rationale |
   133→|---|---|---|
   134→| Table names | `snake_case`, **plural** (`students`, `fee_payments`) | SRS §7 + PostgreSQL idiom. |
   135→| Column names | `snake_case`, singular (`name`, `organization_id`) | SRS §7. |
   136→| Primary key | `id`, type `uuid`, default `uuid_generate_v4()` | SRS §7 + BP9. |
   137→| Foreign key | `{referenced_table_singular}_id` (`student_id`, `branch_id`) | SRS §7. |
   138→| Timestamps | `*_at` suffix, type `timestamptz` (`created_at`, `paid_at`) | SRS §7. |
   139→| Boolean columns | `is_*` or `has_*` prefix (`is_active`, `has_arabic_name`) | Self-documenting. |
   140→| Money columns | `numeric(14, 2)` (BDT, **not** integer paisa) | SRS §3.6 — mock layer uses taka. |
   141→| Enums | `snake_case` constants in a Postgres enum (`'present'`, `'absent'`) | SRS §7. |
   142→| Junction tables | `{a_singular}_{b_plural}` (`role_permissions`, `student_guardians`) | SRS §7. |
   143→| Prisma model | `camelCase` Singular mapped to plural table via `@@map("students")` | BP8. |
   144→| Schema | `public` (default) | SRS §7. |
   145→
   146→### Base Mixin (applied to EVERY table except `organizations`)
   147→
   148→Every table carries these 8 columns. They are omitted from the per-table
   149→column listings in `DATA_DICTIONARY.md` for brevity, but they ALWAYS exist.
   150→
   151→| Column | Type | Nullable | Default | Notes |
   152→|---|---|---|---|---|
   153→| `id` | `uuid` | NO | `uuid_generate_v4()` | PK |
   154→| `organization_id` | `uuid` | NO | — | FK → `organizations.id` (tenant isolation) |
   155→| `branch_id` | `uuid` | YES | NULL | FK → `branches.id`. NULL only for platform-level rows (`organizations` itself, the global seed `permissions` catalog). |
   156→| `created_at` | `timestamptz` | NO | `NOW()` | Record creation timestamp. |
   157→| `updated_at` | `timestamptz` | NO | `NOW()` | Updated via Prisma middleware or DB trigger. |
   158→| `deleted_at` | `timestamptz` | YES | NULL | Soft-delete timestamp (BP7). NULL = active. |
   159→| `created_by` | `uuid` | YES | NULL | FK → `users.id` of creator. |
   160→| `updated_by` | `uuid` | YES | NULL | FK → `users.id` of last updater. |
   161→
   162→> **Exception:** `organizations` itself has no `organization_id` (it IS the
   163→> tenant root). `permissions` catalog rows may have NULL `organization_id`
   164→> (they are seeded globally, not per tenant).

   168→## Multi-Tenant Isolation Strategy
   169→
   170→> **BP1 (Governing Principle #1):** Every query MUST be scoped by
   171→> `organization_id` + `branch_id`. No exceptions.
   172→
   173→### Three-level tenancy
   174→
   175→```
   176→organization (tenant)
   177→└── branch (campus)
   178→    └── record (any table)
   179→```
   180→
   181→### Scoping rules
   182→
   183→| Layer | Column value | Visibility |
   184→|---|---|---|
   185→| Platform (`super-admin`) | `organization_id = NULL` allowed | All tenants |
   186→| Tenant (`authority`, `administrator`, …) | `organization_id = <tenant>` | One tenant, all its branches |
   187→| Branch (`teacher`, `storekeeper`, …) | `organization_id = <t>` + `branch_id = <b>` | One branch only |
   188→| Self (`guardian`, `student`) | Above + `student_id IN (linked)` | Own / linked records only |
   189→
   190→### Enforcement
   191→
   192→1. **Prisma middleware** (BP1, SRS §7) injects `where: { organization_id, branch_id }` on every read and every create.
   193→2. **API middleware** (BP2, Phase B2.2) extracts `organization_id` + `branch_id` from the JWT session and refuses queries that cross scopes (HTTP 403).
   194→3. **Database RLS (Row-Level Security)** — optional hardening layer for production (Phase B9). When enabled, every table gets a policy like:
   195→   ```sql
   196→   CREATE POLICY tenant_isolation ON students
   197→     USING (organization_id = current_setting('app.organization_id')::uuid);
   198→   ```
   199→
   200→### Cross-tenant reads
   201→
   202→`super-admin` reads use `SET LOCAL app.organization_id = NULL` to bypass
   203→the policy. Cross-tenant writes (provisioning a new tenant) go through
   204→the dedicated `tenant.provision` permission gate.

   208→## Index Strategy
   209→
   210→> **SRS §7.3 — Indexing Rules.** Every query that the mock API supports must
   211→> hit an index. The mock API surfaces these access patterns; we mirror them
   212→> at the DB level.
   213→
   214→### Mandatory indexes (on EVERY table)
   215→
   216→| Index | Columns | Why |
   217→|---|---|---|
   218→| `idx_{table}_org_branch` | `(organization_id, branch_id)` | Composite — every query starts with tenant scope. |
   219→| `idx_{table}_deleted_at` | `(deleted_at)` WHERE `deleted_at IS NULL` | Partial index — soft-delete filter is on every read. |
   220→| `idx_{table}_created_at` | `(created_at DESC)` | Sort by recent (dashboards, audit). |
   221→
   222→### Per-table indexes (selected)
   223→
   224→| Table | Index | Columns |
   225→|---|---|---|
   226→| `students` | `idx_students_code` | `(organization_id, code)` UNIQUE |
   227→| `students` | `idx_students_class_section` | `(class_id, section_id)` |
   228→| `students` | `idx_students_guardian` | `(guardian_id)` |
   229→| `attendance_records` | `idx_att_records_student_date` | `(student_id, session_id)` UNIQUE |
   230→| `attendance_sessions` | `idx_att_session_class_date` | `(class_id, section_id, date)` UNIQUE |
   231→| `fee_payments` | `idx_fee_payments_receipt` | `(organization_id, receipt_no)` UNIQUE |
   232→| `fee_payments` | `idx_fee_payments_student` | `(student_id, collected_at DESC)` |
   233→| `ledger_entries` | `idx_ledger_voucher` | `(organization_id, voucher_no)` UNIQUE |
   234→| `ledger_entries` | `idx_ledger_date` | `(date DESC)` |
   235→| `ledger_entries` | `idx_ledger_debit_credit` | `(debit_account_id, credit_account_id)` |
   236→| `accounts` | `idx_accounts_fund` | `(fund)` — Zakat isolation queries |
   237→| `marks` | `idx_marks_unique` | `(exam_id, student_id, subject_id)` UNIQUE |
   238→| `results` | `idx_results_unique` | `(exam_id, student_id)` UNIQUE |
   239→| `library_issues` | `idx_issues_open` | `(book_id, returned_at)` WHERE `returned_at IS NULL` |
   240→| `audit_logs` | `idx_audit_entity` | `(entity_type, entity_id, created_at DESC)` |
   241→| `notices` | `idx_notices_branch_audience` | `(branch_id, audience, sent_at DESC)` |
   242→
   243→### Money columns
   244→
   245→Always `numeric(14, 2)` — never `integer` paisa. Rationale: SRS §3.6 +
   246→the mock layer is already in taka (BDT). 14 digits supports up to
   247→৳999,999,999,999.99 — more than enough for a madrasha.

   251→## Enum Definitions
   252→
   253→> Postgres `CREATE TYPE` enums. In Prisma these are declared as
   254→> `enum Foo { ... }` blocks at the top of `schema.prisma`.
   255→
   256→| Enum | Values | Used by |
   257→|---|---|---|
   258→| `Role` | `super-admin`, `authority`, `administrator`, `accountant`, `teacher`, `storekeeper`, `guardian`, `student` | `users.role_id` (via FK → `roles.code`) |
   259→| `Gender` | `male`, `female` | `students.gender` |
   260→| `StudentStatus` | `active`, `graduated`, `withdrawn` | `students.status` |
   261→| `AttendanceStatus` | `present`, `absent`, `late`, `leave` | `attendance_records.status` |
   262→| `ExamStatus` | `draft`, `marks-entry`, `published` | `exams.status` |
   263→| `MarkGrade` | `a-plus`, `a`, `a-minus`, `b`, `c`, `d`, `f` | `marks.grade` |
   264→| `FundType` | `general`, `zakat` | `accounts.fund` |
   265→| `AccountType` | `asset`, `liability`, `equity`, `income`, `expense` | `accounts.type` |
   266→| `FeeMethod` | `cash`, `bank`, `mobile` | `fee_payments.method` |
   267→| `LedgerStatus` | `pending`, `posted`, `rejected` | `ledger_entries.status` |
   268→| `ApprovalType` | `expense`, `purchase`, `discount`, `admission` | `approvals.type` |
   269→| `ApprovalStatus` | `pending`, `approved`, `rejected` | `approvals.status` |
   270→| `NoticeAudience` | `all`, `class`, `guardians`, `staff` | `notices.audience` |
   271→| `DocumentType` | `pdf`, `image`, `spreadsheet`, `other` | `documents.type` |
   272→| `ApprovalDecision` | `approved`, `rejected` | used inside approval flow audit |
   273→| `AdmissionStatus` | `pending`, `approved`, `rejected`, `enrolled` | `admissions.status` |
   274→
   275→> **`PermissionCode`** is **not** an enum in Postgres — it's a `varchar(64)`
   276→> column on the `permissions` table with a CHECK against the 110+ codes
   277→> listed in `src/lib/auth/permissions.ts`. Reason: the catalog is
   278→> extensible (modules can register new codes at runtime), so it cannot
   279→> be a static enum.

  1239→## Constraints Catalog
  1240→
  1241→The constraints below are **cross-cutting** (apply to multiple tables). Per-table constraints are documented in `DATA_DICTIONARY.md`.
  1242→
  1243→### Money CHECK constraints
  1244→
  1245→```sql
  1246→-- Every money column must be >= 0
  1247→ALTER TABLE fee_installments  ADD CHECK (amount >= 0);
  1248→ALTER TABLE fee_payments      ADD CHECK (amount >= 0);
  1249→ALTER TABLE ledger_entries    ADD CHECK (amount >= 0);
  1250→ALTER TABLE zakat_transactions ADD CHECK (amount >= 0);
  1251→ALTER TABLE donations         ADD CHECK (amount >= 0);
  1252→ALTER TABLE cash_bank_transfers ADD CHECK (amount >= 0);
  1253→```
  1254→
  1255→### Unique constraints (composite, multi-tenant)
  1256→
  1257→```sql
  1258→-- A student code is unique per organization (NOT globally)
  1259→ALTER TABLE students ADD UNIQUE (organization_id, code);
  1260→-- A receipt number is unique per organization
  1261→ALTER TABLE fee_payments   ADD UNIQUE (organization_id, receipt_no);
  1262→ALTER TABLE ledger_entries ADD UNIQUE (organization_id, voucher_no);
  1263→ALTER TABLE accounts       ADD UNIQUE (organization_id, code);
  1264→ALTER TABLE branches      ADD UNIQUE (organization_id, code);
  1265→ALTER TABLE roles         ADD UNIQUE (organization_id, code);
  1266→```
  1267→
  1268→### Balanced ledger constraint
  1269→
  1270→```sql
  1271→-- A single voucher's debits must equal credits (Golden Flow §3.6)
  1272→-- Enforced at app layer (B6.3) because Postgres can't easily CHECK
  1273→-- across two columns of the same row when the row is the unit.
  1274→-- Simpler form: each row is balanced by design (one debit, one credit).
  1275→-- Multi-line vouchers use a voucher_group_id + an aggregate CHECK view.
  1276→```
  1277→
  1278→### Fund isolation CHECK
  1279→
  1280→```sql
  1281→-- A Zakat account may only appear in zakat-fund ledger entries
  1282→ALTER TABLE ledger_entries ADD CONSTRAINT chk_fund_consistency
  1283→  CHECK (
  1284→    fund = 'general' OR
  1285→    (debit_account_id IN (SELECT id FROM accounts WHERE fund='zakat')
  1286→     AND credit_account_id IN (SELECT id FROM accounts WHERE fund='zakat'))
  1287→  );
  1288→```
  1289→
  1290→> In practice this is enforced via a trigger because Postgres CHECK
  1291→> cannot reference other tables. See migration `B1.3_fund_isolation.sql`
  1292→> (Phase B1).
  1293→
  1294→### No-self-approve (D16)
  1295→
  1296→```sql
  1297→-- Approvals: requested_by != decided_by (enforced at API layer too)
  1298→ALTER TABLE approvals ADD CONSTRAINT chk_no_self_approve
  1299→  CHECK (requested_by IS DISTINCT FROM decided_by);
  1300→```
