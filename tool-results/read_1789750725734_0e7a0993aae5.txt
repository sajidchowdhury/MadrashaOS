   298→### Verification notes
   299→
   300→- **Sticky footer:** `AppShell` root wrapper is `min-h-screen flex flex-col`;
   301→  `Footer` carries `mt-auto`. When content is shorter than one viewport, the
   302→  footer pins to the bottom (no floating gap). When content overflows, the
   303→  footer is pushed down naturally (no overlay). Verified by visual
   304→  inspection of `/`, `/dashboard`, `/students`, `/dev/walkthroughs`.
   305→- **No horizontal scroll at 375px:** every page in `(app)/` and `(public)/`
   306→  uses mobile-first utilities (`grid-cols-1 sm:grid-cols-2`). The fees
   307→  table is the only known horizontal-scroller (acceptable per WCAG for
   308→  dense data — surfaced in `/dev/a11y`).
   309→- **Hamburger drawer:** opens from the start side (`inset-y-0 start-0`),
   310→  width `w-64 max-w-[85vw]` (so it never overflows on small phones),
   311→  includes a header row with a Close (X) button, and the overlay click also
   312→  dismisses. Verified in `AppShell.tsx` lines 49–78.
   313→- **Safe area insets:** the footer uses `px-4 py-3 md:px-6`; the
   314→  MobileBottomActionBar uses safe-area-aware padding. On iOS devices the
   315→  footer respects bottom safe-area insets via the AppShell wrapper.
   316→- **RTL reflow:** the mobile drawer uses logical-property utilities
   317→  (`start-0`) so it slides in from the right in Arabic mode. The footer
   318→  flex row reverses automatically via `ms-auto / me-auto`.
