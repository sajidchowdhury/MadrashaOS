    17→## 0. Purpose & Relationship to the UI/UX Plan
    18→
    19→The UI/UX Coding Plan (`MADRASHAOS_CODING_PLAN.md`) delivered a fully workable frontend running on **mock data** — 54 routes, 30 components, 5 dashboards, 8 flows, all functional but with no real database or backend.
    20→
    21→This plan is the **backend mirror**. It converts the mock data layer (`src/lib/mock/`) into a real PostgreSQL-backed API. The swap path is designed to be **zero-component-change**: the TanStack Query hooks (`useStudents`, `useFeePlans`, etc.) call `mockApi` today and will call the OpenAPI-generated client tomorrow — same interface, different data source.
    22→
    23→> **Definition of Done for this plan:** after the final session, the application runs end-to-end on a real PostgreSQL database with real authentication, real CRUD endpoints for all 40+ modules, real permission enforcement, and real data persistence. The frontend swaps `mockApi` → generated client with zero component changes.

    27→## 1. Governing Principles (carried over from SRS + UI/UX plan)
    28→
    29→Every line of backend code must satisfy:
    30→
    31→| # | Principle | How it shows up in backend code |
    32→|---|---|---|
    33→| BP1 | Multi-Tenant Isolation | Every table has `organization_id` + `branch_id`; Prisma middleware injects tenant scope on every query (SRS §3.1, §7) |
    34→| BP2 | Permission-Aware API | Every endpoint checks permission codes via middleware before executing (SRS §5.1, §6.2) |
    35→| BP3 | Balanced Ledger (Golden Flow) | Fees, donations, Zakat, salaries post through the Accounting ledger as balanced debit=credit entries (SRS §3.6) |
    36→| BP4 | Idempotency | All write endpoints accept `Idempotency-Key` header; duplicate requests return cached response (SRS §6.5) |
    37→| BP5 | Audit Trail | Every write to audited entities produces a field-level audit diff record (SRS §2.1.4, §3.4) |
    38→| BP6 | Fund Isolation | Zakat funds never co-mingle with general funds; enforced at the account level (SRS §3.7, C6) |
    39→| BP7 | Soft Delete | No hard deletes on financial/student records; `deleted_at` column + Prisma middleware filters them out |
    40→| BP8 | Snake Case | Database tables/columns use `snake_case` (SRS §7); Prisma models use `camelCase` with `@@map` |
    41→| BP9 | UUID Primary Keys | All tables use `uuid` PKs with `default(uuid())` (SRS §7) |
    42→| BP10 | OpenAPI-First | API spec is generated from code (not hand-written); frontend client is generated from spec |
    43→
    44→**Hard constraints from SRS (non-negotiable):**
    45→- C1: Core tasks reachable in ≤3 clicks (frontend enforces; backend supports with efficient endpoints)
    46→- C3: No financial data visible to Teacher role (enforced at API level — 403 if Teacher requests `/api/v1/fees`)
    47→- C6: Zakat funds isolated (enforced at DB level — Zakat account has `fund: "zakat"` flag)
    48→- C7: Requester cannot approve own request (enforced at API level — 403 if `requestedBy === currentUser`)
    49→- C8: Public visitor cannot reach protected endpoints (enforced at middleware level — 401 for unauthenticated)

    53→## 2. Mock-to-Real Swap Strategy
    54→
    55→The existing mock layer is the **data contract**:
    56→
    57→```
    58→src/lib/mock/mockApi.ts          →  src/lib/api/client.ts (generated from OpenAPI)
    59→src/lib/mock/fixtures/*.ts       →  PostgreSQL database (seeded via Prisma)
    60→src/lib/mock/types.ts            →  Prisma-generated types (same shape)
    61→src/lib/query/client.ts          →  UNCHANGED (hooks call client.ts, which swaps source)
    62→```
    63→
    64→**The swap is a one-file change:** replace `mockApi` import in `src/lib/query/client.ts` with the generated OpenAPI client. Zero component changes.
